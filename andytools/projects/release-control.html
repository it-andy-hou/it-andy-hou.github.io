发布控制管理系统

面向金融证券运维团队打造的 Windows 端发布流程可视化管理工具。在不改动现有发布脚本的前提下，通过 SSH 调度现有命令，将原有 CLI 交互升级为可视化控制台，支持生产/预发布双环境切换，完整记录每次发布过程，让运维发布有据可查、操作可回溯。

🚀 发布控制

核心功能模块，通过 SSH 调度服务器现有发布脚本，将命令行操作转化为可视化流程管理。

  • 双环境切换：支持生产（pro）/ 预发布（pre）环境一键切换，任务清单随环境独立维护
  • 可视化任务清单：支持单条添加、批量粘贴命令行批量导入，自动解析 req / op / 服务名等字段
  • 发布 & 回滚：每条任务可独立执行发布或回滚操作，对应调用 wzq_release_control.py -release / -roll
  • 全部发布（串行）：一键串行执行清单内所有待发布任务，任一任务失败立即中止，保障发布原子性
  • 实时日志输出：发布过程逐行实时推送到终端日志面板，支持查看详细服务端日志文件
  • 任务状态追踪：每条任务独立展示执行状态（待发布 / 执行中 / 成功 / 失败），耗时精确到秒
  • 互斥锁保护：任务执行期间禁止重复触发，防止并发冲突导致发布异常
  • 企业微信推送：发布完成或失败后自动推送 Webhook 通知，包含任务详情与执行结果
  • 密码安全：SSH 密码支持明文/密文查看切换，本地 JSON 加密存储

📋 发布历史

独立存储每次发布任务的完整记录，与当前发布清单数据隔离，清空清单不影响历史数据。

  • 自动归档：任务执行完成后自动写入发布历史，包含模块名、环境、状态、耗时、时间戳
  • 模块 & 日期筛选：支持按服务模块名称和发布日期组合筛选，快速定位历史记录
  • 终端日志回溯：每条历史记录可查看当次的终端日志输出详情
  • 服务端日志：可读取服务器上对应的 work.{server}.log.{date} 日志文件内容
  • 数据隔离保障：清空发布清单操作只清除当前任务列表，历史数据持久保留，不受影响
  • 页面自动刷新：切换到发布历史 Tab 时自动加载最新数据，无需手动刷新

📦 模块清单

通过 SSH 读取服务器端配置文件，解析并可视化展示所有服务模块信息，方便运维人员快速查阅。

  • 配置文件解析：自动读取并解析 machine.pre.conf / machine.pro.conf，提取服务名、主机列表等信息
  • 新旧格式兼容：同时兼容旧版配置格式与新版格式，向下兼容无历史包袱
  • 关键字筛选：支持按服务名称关键字实时过滤，防抖优化避免频繁渲染
  • 增量渲染：列表采用增量更新策略，筛选时仅更新变动节点，避免全量重绘影响性能
  • 空状态提示：无数据或筛选无结果时展示友好的空状态提示，保留页面框架结构

🖥️ 服务清单

管理发布相关的服务器连接信息，支持远程读取配置并安全存储。

  • 服务器信息管理：维护 IP、端口、账号等 SSH 连接信息，支持增删改查
  • 敏感信息保护：密码字段脱敏显示，页面不明文展示，存储时加密处理
  • 远程配置读取：通过 SSH 连接服务器，实时读取远端配置文件内容，同步到本地
  • 批量操作前校验：执行批量发布任务前自动校验服务器连接状态，连接异常时提示并阻止操作

🏷️ 注册版本

解析服务器端版本注册日志，以表格形式可视化展示各模块的版本注册历史，方便快速核查。

  • 日志文件解析：自动扫描并解析服务器端 reg.*.log.* 日志文件，提取版本注册记录
  • 表格化展示：以结构化表格呈现版本号、模块名、注册时间、操作单号等关键信息
  • 多模块汇总：一次性汇总所有模块的注册记录，无需逐一 SSH 查看日志文件
  • 时间戳兼容：兼容 ISO 8601 等多种时间格式，确保日志解析不因格式差异失败

🏗️ 技术架构

前端渲染层

Electron Renderer + 原生 HTML5 / CSS3 / JavaScript，Tab 单页应用架构，无框架依赖，保持 SSH 连接状态不丢失

主进程逻辑层

Node.js + node-ssh，IPC 通信，SSH 连接管理，Promise 串行任务链，互斥锁防死锁设计

数据持久化层

JSON 文件持久化存储任务详情、发布历史、状态与日志；原子写入防止竞态条件

✨ 设计亮点

互斥锁串行执行

任务执行期间全局加锁，防止重复触发与并发冲突，确保发布操作的原子性与可预期性。

数据完全隔离

发布清单与发布历史数据独立存储，清空当前清单不会影响历史记录，确保历史数据永久可查。

单页应用保持连接

各功能模块整合为 Tab 单页应用，切换 Tab 不重载页面，SSH 连接状态在会话内持续保持。

增量渲染优化

任务列表与模块清单均采用增量 DOM 更新策略，避免 innerHTML 全量重绘导致的性能问题与焦点丢失。
